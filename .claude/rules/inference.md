# `internal/inference`

Two roles, `Chatter` (`Chat` and `CountTokens`, in `chat.go`) and `Embedder` (`CreateEmbedding`, in `embedding.go`), and `Provider` (`provider.go`), which is both, for vendors that offer both through one client. `OpenAIProvider`, `OllamaProvider` and `GeminiProvider` are `Provider`s; `ClaudeProvider` is a `Chatter` only (via the official Anthropic Go SDK) and `VoyageProvider` an `Embedder` only, with no method for the role their vendor lacks; `MockProvider` (`mock.go`) implements both for tests. Code that only chats takes a `Chatter` and code that only embeds an `Embedder` (`BuildIndex`, `CosineRanker`, `runIndex`); `inference.Provider` appears only where one instance fills both roles (`cli`'s `buildProvider` and `ProviderFactories.Chat`). `VoyageProvider` embeds via hand-rolled HTTP (no official Go SDK exists), supporting both Voyage's `embed()` and `contextualized_embed()` endpoints auto-selected by model name.

`CreateEmbedding` takes an `EmbeddingTaskType` (`EmbeddingTaskDocument` for indexing, `EmbeddingTaskQuery` for search); `EmbeddingTaskType.Pick(document, query)` lets a provider map the role onto its own backend's convention in one line. `GeminiProvider` maps it to the Gemini API's own `TaskType` string; `OllamaProvider` maps it via a small `embeddingPrefixConventions` table to nomic-embed-text's `search_document:`/`search_query:` prefix convention (only when the embed model name's last `/`-separated segment starts with `nomic-embed`, so a registry- or namespace-qualified name like `my-registry:5000/nomic-embed-text` still matches; adding a second model's convention is a new table entry, not a new branch); `VoyageProvider` maps it to Voyage's `input_type` field the same way; `OpenAIProvider` ignores it (see `docs/arch/0003-embedding-task-role.md` and `docs/arch/0004-decoupled-chat-and-embedding-providers.md`).

As of `docs/arch/0016-llm-suggested-remediation.md`, `SuggestRemediation` shares its retry/JSON-parsing logic with `AnalyzeDrift` via a generic `chatJSON[T]` helper, and is only ever called by `internal/analysis.Engine.Run` after a violation is already confirmed.

## Footguns

- **The `--since` diff instructions live in `inference.ChatPromptDiff`, a user prompt, not the system prompt.** `llm.system_prompt` replaces the system prompt wholesale, so a custom one needs nothing extra, and editing `ChatPromptDiff` changes the analysis cache key. The engine verifies that a quote is in a changed line but cannot tell a required removal from a fix, so a removal finding rests on the model. See `docs/arch/0030-judge-the-change-under-since.md`.
- **`OllamaProvider.CountTokens` must use `num_predict: 1`, not `0`.** `0` does not suppress generation on this codebase's Ollama version (it still runs a full completion); `1` reliably stops after exactly one token and still returns the real `prompt_eval_count`. See `docs/arch/0002-provider-scoped-token-counting.md` for the full rationale. `CountTokens` for Ollama/Gemini is also a live network call, so `truncateToTokenLimit` can cost several round-trips per oversized file — don't assume truncation is free local computation when touching that path.
- **`OllamaProvider.CreateEmbedding` silently skips the nomic prefix for any embed model whose last `/`-separated segment isn't `nomic-embed*`.** There's no error or warning — a typo'd or swapped `vector_store.embedding_model` just stops getting the `search_document:`/`search_query:` prefix with no signal that asymmetric retrieval quietly turned off.
- **Changing how embeddings are computed (e.g. adding the nomic task-role prefix) makes an existing index stale, but nothing detects it.** `LocalStore.CalculateHash` only hashes the model name plus each ADR's `RelPath`/`Content`/`ID` (and rules, when present), and `PgStore.CalculateHash` is a hardcoded `"remote"` constant — neither changes when the *embedding computation itself* changes between binary versions. Upgrading past a change like this without re-running `archguard index` compares newly-computed query embeddings against stale document embeddings from before the change, silently degrading ADR-match relevance with no error. If you change what text/config goes into an embedding call, call this out in the release notes as requiring a re-index.
